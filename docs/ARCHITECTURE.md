## Поток данных

1. Игрок создаёт комнату → `createMatch()` → WebSocket комната
2. Игроки присоединяются → `addPlayer()` → broadcast `player_joined`
3. Запуск матча → Snake Draft → заполнение ботами → `match_started`
4. Игровой цикл: `rule_changed` → ответы → `round_result` (×15)
5. Завершение → `match_ended` → результаты

## Ключевые решения

### Почему Socket.io?
Для синхронной игры необходим real-time. Альтернативы:
- **ws**: нет комнат и авто-реконнекта
- **SSE**: однонаправленный канал
- **WebRTC**: избыточен

### Почему In-Memory Store?
Активные матчи хранятся в памяти для производительности. PostgreSQL используется для долгосрочного хранения.
